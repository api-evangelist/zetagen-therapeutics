## Notes for agents

- There is no developer portal, no API key, no OAuth and no signup. Read operations are open.
- Press releases and peer-reviewed publications are both stored as ordinary WordPress posts. The
  only discriminator is the category term: id 2 is `press-release` (26 posts), id 7 is
  `publications` (6 posts). There is no custom post type.
- `per_page` is capped at 100 and returns HTTP 400 `rest_invalid_param` above it — it does not
  clamp.
- Prefer `GET /wp/v2/search` then dereference `_links.self`, over paging whole collections.
- `GET /wp/v2/users` answers anonymously on this deployment and returns personal data. It is
  documented in the OpenAPI for contract completeness and deliberately excluded from every skill in
  this repo. Do not use it.
- The company's own clinical and regulatory claims live in the press releases. Treat them as
  company statements, not as independent verification.
